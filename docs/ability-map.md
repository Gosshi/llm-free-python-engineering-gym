# Ability map

| 職種 | このリポジトリで観測できる主な能力 | 課題外で別途確認すべき能力 |
| --- | --- | --- |
| ミドルレベルのソフトウェアエンジニア | 要件理解、実装の正確性、テスト、デバッグ、基本設計 | プロダクト理解、協働実績、継続的な成果 |
| シニアソフトウェアエンジニア | 保守性、設計判断、性能・安全性の配慮、技術説明 | 複数チームへの影響、複雑な成果の継続性 |
| テックリード | 設計トレードオフ、技術的文章、レビュー観点、技術的影響力の基礎 | 合意形成、技術方針の推進、他者の生産性向上 |
| プレイングマネージャー | 実装と設計の基礎、優先順位、説明力 | 目標設定、評価、採用、育成、組織運営 |
| エンジニアリングマネージャー候補 | 技術的判断の理解と説明 | 評価、採用、育成、組織運営、ピープルマネジメント実績 |

実装課題だけではピープルマネジメント能力は測れない。テックリードには実装力だけでなく、
設計判断と技術的影響力が必要である。EM候補には評価、採用、育成、組織運営など別の
実績確認が必要である。

このリポジトリの単一課題、または総合点だけで職位を判定しない。複数課題の推移、実務の
成果、協働とマネジメントの証拠を合わせて判断する。
